About This Software

Monitor current from one or two meters, view live plots, and calculate accumulated charge. Measurements are saved automatically to CSV files.

Connect through a serial port or a TCP serial server. On Linux, DAQ_Master and GDDAQ integration can start and stop recording automatically and name files by acquisition run.

For connection setup, units, alarms, and DAQ integration, see Tutorial in the program.

Update History

Entries describe changes made at each release. Later entries may replace earlier settings or behavior.

v1.1.0 (2026-09-23; updated 2026-09-24)

  • GDDAQ memory detection: Added Process Memory (root) alongside run.log monitoring. It reads acquisition state directly from GDDAQ, so restart detection does not depend on data being written to disk.
  • Detection interval: Memory state is sampled once per second. Short runs or pauses that occur entirely between samples may still be missed.
  • GDDAQ version selection (2026-09-24): Added GDDAQ Version, with GDDAQ-CAEN (20260709) as the supported target. This setting is available in memory mode while disconnected. Recompiled GDDAQ binaries may need compatibility checks.
  • Automatic run selection: Log mode follows the highest numbered run folder; memory mode follows the active run. The manual Run Number setting has been removed.
  • Data location: Both methods append to CurrentData/run_XXXXX.csv beside the GDDAQ data directory. Files previously saved under raw/CurrentData/ are not moved or merged automatically.
  • Run changes: When the run number or data directory changes, recording switches to the corresponding CSV. Log mode closes the previous recording and waits if the new run has no valid Start entry.
  • Memory connection recovery: Recording stops when GDDAQ or the helper is confirmed to have exited. If no valid state arrives for 3 seconds, recording stops on the next check; repeated old or error states do not extend this wait.
  • Resuming after an interruption: A running helper resumes monitoring when valid GDDAQ state returns. If the helper exits, reconnect the GDDAQ link manually.
  • Automatic start retries: GDDAQ recording retries after directory, device, or CSV startup failures. The status bar and event log report the cause without repeated error dialogs. In memory mode, a configured data directory is optional.
  • Log-mode restarts: Newer data files can identify a restart in the same run folder. Recording resumes in the same CSV, but may be delayed until data is written to disk. Short segments may be missed; suspected gaps produce a warning.
  • Append mode: GDDAQ recording always appends to an existing run file, matching DAQ_Master behavior.
  • Stop handling: GDDAQ stop events and process exits stop only recordings started by GDDAQ.
  • Manual control: Taking manual control exits DAQ link mode. Confirmation is requested before a manual start, or before stopping while the external DAQ is still acquiring.

v1.0.0 (2026-08-30)

DAQ integration

  • Added separate, mutually exclusive DAQ_Master and GDDAQ options under Connect to DAQ. DAQ integration is available on Linux.
  • Added GDDAQ start/stop detection through run.log, with process-exit detection through pgrep.
  • Added settings for the GDDAQ data directory, process name, and target run number. Automatic run selection replaces the last option in v1.1.0.
  • Improved recovery after failed GDDAQ startup. DAQ stop events and disabling a link apply only to recordings started by that DAQ system.
  • DAQ_Master recordings use append mode. Link settings are locked during recording, and enabling one link disables the other.

Monitoring and everyday use

  • Added pulse mode to Status Monitor Settings. It skips PEAK/DROP detection and checks for sustained near-zero current.
  • Added a ZERO alarm sound, enabled by default and configurable in Status Monitor Settings. Fixed recovery from ZERO in DC mode.
  • Added an event log bar and window. The latest 100 events are retained in memory, with severity colors and start/stop sources. Logs are cleared when the application closes.
  • Disabled Pulse Reminder by default. Reminder, About, and Tutorial windows allow continued operation of the main window; reopening About or Tutorial brings the existing window forward.
  • Added path completion for save-file and GDDAQ directory inputs. Snapshots created within the same second now receive distinct filenames.

Communication and measurement fixes

  • Added Modbus response validation, including address, function, length, and CRC checks. Invalid frames are discarded, and receive buffers are resynchronized.
  • Improved handling of fragmented TCP responses, stale data, disconnects, and serial receive timing. Receive timeouts adapt to the update interval.
  • Added separate warnings for persistent response timeouts and CRC/format errors. Warnings are tracked per channel, with repeated messages suppressed.
  • Rejected duplicate connection addresses in dual-channel mode. Connection and file controls are locked while recording.
  • Reset the integration baseline after missing or filtered frames to avoid carrying the previous reading across a data gap.
  • Applied current limits independently to each channel using absolute values. A limit of 0 disables the amplitude limit; NaN and Inf readings are still rejected.
  • Stored status thresholds in mA so their meaning remains consistent across display units. Updated the history during ZERO to reduce false PEAK warnings after recovery.

File handling and application reliability

  • Fixed filename parsing for directories containing .csv. When numbering wraps from 9999 to 0000, existing filenames are skipped.
  • Improved cleanup after failed startup and on exit. Closing the application without an active recording no longer advances the filename.
  • Improved single-instance locking and added a timeout to process checks. Data folders are opened without passing their paths through a shell.
  • Reduced plot-refresh and hover-processing overhead. Improved resource lookup in source and packaged builds, snapshot metadata handling, and repeated-error reporting.
