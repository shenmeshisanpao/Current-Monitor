About This Software

This software is designed for real-time monitoring of dual-channel current data and charge integral calculation. It supports automatic data saving, graphical visualization, and flexible Single/Dual channel operation modes.

Update History

v1.1.0 (2026-09-23, Latest)

  • GDDAQ Memory-Read Link Mode: Added a second GDDAQ detection method alongside the existing run.log monitoring. The new "Process Memory (root)" option reads the acquisition state directly from the gddaq process memory, avoiding data-flush delays in restart detection. Both the helper and GUI still poll once per second; transitions entirely between memory samples may be missed.
  • GDDAQ Run Selection & Storage: Both methods now select runs automatically (highest numbered folder for run.log; active run for memory), with no manual Run Number setting. CSV files append to <parent of raw>/CurrentData/run_XXXXX.csv. Existing files under raw/CurrentData are not moved or merged.
  • GDDAQ Run Boundaries: Observed run/folder changes close the old CSV before starting the new one, even if an intervening Stop was not sampled. A new log-mode run without a valid Start waits with the old recording closed.
  • Memory Link Recovery: The helper publishes a heartbeat every second, including unchanged and error states, and reports the active thread run number. Confirmed DAQ/helper exit stops linked recording immediately. Three seconds without a valid state stops recording on the next poll; fresh error heartbeats do not extend this deadline. A live helper resumes following after valid state returns; an exited helper requires manual reconnection.
  • Automatic Start Recovery: Optional memory-mode folder configuration now works. Directory, device and CSV failures release resources and remain retryable, with deduplicated logs and no modal error dialogs. Memory offsets and one-second polling remain unchanged.
  • GDDAQ Restart Tracking: Same-folder restarts are detected by data files newer than run.log and auto-resumed into the same run_XXXXX.csv, with flush-delay/missed-short-segment limits, an orange hint + WARNING, a 10 s post-Stop grace and 2 s freshness threshold, and crash handling if gddaq disappears.
  • Bug Fix — GDDAQ File Mode: Runs auto-started by GDDAQ now force append mode (same as DAQ_Master): a pre-existing run_XXXXX.csv is never silently overwritten, and no modal overwrite-confirmation dialog can appear inside the polling timer callback.
  • Bug Fix — GDDAQ Stop Scope: A Stop block in run.log (or a process crash) now only stops runs that were auto-started by GDDAQ. Manually started monitoring is no longer interrupted, consistent with DAQ_Master behavior.
  • Link-Mode Ownership: In link mode, start/stop is controlled by the external DAQ software; any manual intervention exits link mode.

v1.0.0 (2026-08-30)

  • Bug Fix — Comprehensive Code Review: A full review pass over the entire codebase. Issues fixed, by category:
    • Communication Reliability:
      • Modbus response frames are now validated (slave address, function code, exception bit, byte count, CRC); invalid frames are discarded and the RX buffer is resynchronized, preventing noise/misaligned bytes from corrupting readings.
      • TCP reception now loops until a complete 9-byte frame arrives (handles packet fragmentation), detects peer disconnects, and drains stale bytes before each request to guarantee strict request–response pairing.
      • Serial resynchronization waits for in-flight bytes before flushing the buffer; TCP/serial receive timeouts now scale with the update interval (prevents UI freeze at small intervals).
      • Persistent CRC/format errors are logged distinctly from timeouts ("check baud rate/wiring"); send and receive error logging are debounced independently per channel so half-recovered links are still reported.
      • Starting with both channels configured to the same port/address is now rejected with a clear warning.
    • Measurement Correctness:
      • Charge integration no longer accumulates phantom charge across communication gaps or filtered frames (integration baseline is reset whenever a frame is dropped).
      • Current validity filter is now per-channel, two-sided, and rejects NaN/Inf; a threshold of 0 disables filtering instead of silently dropping all data.
      • Status Monitor thresholds are stored internally in mA; switching display units no longer shifts threshold semantics. History is updated during ZERO state so recovery no longer triggers a false PEAK.
      • Filename parsing strips only the trailing ".csv" (paths containing ".csv" in directory names are no longer corrupted); filename wrap-around (9999→0000) skips existing files instead of appending into ancient runs.
    • Robustness & Lifecycle:
      • Serial ports and sockets are rolled back if startup fails midway; "Test Port" buttons and port inputs are disabled while monitoring; filename/mode controls are disabled during a run (DAQ-linked state respected).
      • Closing the app without a run no longer auto-increments the filename; DAQ/GDDAQ polling timers are stopped on exit.
      • GDDAQ auto-start failure rolls back to IDLE so the next poll retries instead of skipping the run; GDDAQ run number input is validated; run.log is re-parsed only when modified.
      • Recv-timeout warning threshold fixed for slow sample intervals (was up to 250s, now ~5s); channel timeout states are tracked independently.
      • Pulse reminder dialog is modeless (acquisition keeps running) and destroyed on close (no hidden-dialog accumulation); DAQ_Master START forces append mode (no modal dialog inside timer callbacks); GDDAQ directory errors no longer block the polling timer with modal dialogs.
      • Single-instance lock is per-user and no longer truncates the running instance's PID; pgrep subprocess has a timeout; snapshot filenames are deduplicated within the same second.
    • Security:
      • "Open Data Folder" now invokes the OS handler via subprocess arguments instead of a shell command, eliminating command injection via paths derived from the DAQ status file.
    • Code Quality & Performance:
      • float conversion rewritten with struct (ctypes removed); bare except: clauses replaced; dead code removed (unreachable branches, unused attributes/variables).
      • Plot redraws use draw_idle(); X-axis tick labels are computed only for tick positions; hover closest-point search is vectorized with NumPy; persistent failures no longer flood stdout with tracebacks.
      • Resource paths unified via resource_path() (works from any launch directory and in PyInstaller builds); settings dialog no longer relies on fragile layout indices; snapshot metadata uses live values instead of re-parsing UI labels; path auto-completion models use QFileSystemModel.
  • Bug Fix — DAQ Link Mode Hardening:
    • DAQ_Master mode is now blocked on Windows with a clear warning (the /tmp/daq_status.txt status file is Linux-only), matching the existing GDDAQ behavior.
    • DAQ link menu entries (DAQ_Master / GDDAQ / GDDAQ Settings) are now disabled while monitoring is running, consistent with other run-time configuration locks; enabling one link mode disables the other mode's menu entry until it is turned off.
    • The run trigger source is now tracked: DAQ STOP signals and unchecking a DAQ link mode only stop runs started by that DAQ system — manually started runs are no longer interrupted.
    • DAQ_Master no longer misses the first signal if the status file was deleted and later restored with a preserved (older) timestamp; the modification-time baseline is reset whenever the file is absent.
  • DAQ Integration Overhaul: Restructured "Connect to DAQ" into a submenu with two mutually exclusive options: DAQ_Master (renamed from "Connect to DAQ (beta)") and GDDAQ (new).
  • GDDAQ Support: Added automatic start/stop synchronization with GDDAQ acquisition system by monitoring run.log files. Includes crash detection via pgrep process monitoring.
  • GDDAQ Settings: Added a configuration dialog for GDDAQ data directory, process name, and target run number.
  • Pulse Reminder: Changed default state from enabled to disabled.
  • Path Auto-Completion: The "Save File Name" input and the GDDAQ data-directory input now offer path auto-completion (QCompleter + QFileSystemModel).
  • Non-modal About & Tutorial: The About and Tutorial dialogs are now non-modal and single-instance — they stay open while you operate the main window, and re-opening raises the existing window instead of stacking a new one.
  • Status Monitor Pulse Mode: Added "Pulse Mode" option in Status Monitor Settings. When enabled, spike detection (PEAK/DROP) is skipped and only signal loss is monitored.
  • ZERO Alarm Sound: Added an audible alarm when any channel enters ZERO state. Can be toggled on/off in Status Monitor Settings (enabled by default).
  • Event Log Bar: Added a one-line log bar at the bottom of the main window (below the plot area), showing the most recent event. Click it to open the Event log window.
  • Event Log Window: It records up to 100 events since startup. Logs are kept in memory only and are cleared on exit.
  • Log Severity Colors: Entries are formatted as [time] [level] message and color-coded by importance.
  • Bug Fix — DC Mode ZERO Auto-Recovery: Fixed an issue where the Status Monitor indicator stayed red indefinitely after a ZERO warning in DC mode, even after current recovered.
