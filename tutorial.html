电流实时监控系统使用教程

本教程介绍 cur_raw.py 的操作方法，包括连接电流表、记录数据、设置状态提醒，以及与 DAQ 数据获取程序联动。

作者：Z.C. Zhang。本文修订于 2026 年 9 月 24 日。

首次使用时，请先按“使用教程”完成一次手动采集，确认连接、单位和保存位置正确，再根据需要配置额外功能。

使用教程

1. 连接电流表

给电流表通电，然后根据设备的连接方式接入电脑：

  • USB 串口连接：将电流表连接到电脑的 USB 接口。
  • TCP 网络连接：通过串口服务器传输数据，并在串口服务器中配置 TCP Server 模式。

2. 选择连接方式和通道数量

在菜单栏 Connection 中选择串口模式或 TCP Network Mode，使其与实际接线方式一致。

程序默认使用双通道。如果只连接了一台电流表，请选择 Run → Single Channel Mode (CH1 Only)，或按 Ctrl+Shift+S 切换到单通道模式。此时只需配置 Channel 1，Channel 2 不参与采集。

3. 填写连接地址并测试

在主界面的 Channel 1 和 Channel 2 输入框中，分别填写对应电流表的连接地址，再点击旁边的 Test 按钮测试连接。

连接方式填写内容示例
USB 串口串口设备名/dev/ttyUSB0
TCP 网络IP 地址和端口，以冒号分隔192.168.1.100:4001

表中的地址仅用于说明格式，请替换为实际设备地址。网络地址和端口可在串口服务器的配置页面中查看。

双通道模式下，两个通道必须使用不同的串口或不同的 IP:Port。程序会拒绝重复地址，以免两路请求在同一连接上相互干扰。

在 Linux 下查找 USB 串口

打开终端，执行以下命令，查看系统已识别的 USB 串口：

ls /dev/ttyUSB*

如果存在多个设备，无法确定哪个串口属于电流表，可以在插入电流表之前运行：

dmesg -w

随后连接电流表，观察新增信息。例如，下面这行表示设备被分配到了 /dev/ttyUSB0：

[  124.012] usb 1-1: USB serial device converter now attached to ttyUSB0

确认设备名后，按 Ctrl+C 结束查看，再将完整路径填入程序。如果系统提示无权读取内核日志，可使用 sudo dmesg -w。

4. 核对单位和采集参数

开始采集前，打开 Run → Set Channel Units，为每个通道选择电流表实际输出的单位：mA、μA 或 nA。单位设置会影响读数换算和电荷积分，必须与电流表一致。

串口波特率默认为 9600。如果设备使用其他波特率，请通过 Run → Set Baud Rate 修改。读取间隔默认为 100 ms，可在 Run → Set Update Interval 中调整。

5. 设置数据保存位置

在 Save File Name 中填写 CSV 文件的路径和名称，也可以使用浏览按钮选择位置。默认文件名为 Run_0000.csv；未指定目录时，文件保存在程序的当前工作目录中，该目录不一定是脚本所在目录。

如果同名文件已经存在，可通过 File Mode 选择保存方式：

  • 追加（Append，默认）：保留已有内容，将本次数据写到文件末尾。
  • 覆盖（Overwrite）：重新写入文件。程序会在覆盖已有文件前要求确认。

建议每轮采集使用独立的文件名。需要检查保存位置时，可选择 File → Open Data Folder 打开数据文件夹。

6. 开始监控

点击 Start Monitoring，或按 Ctrl+R。成功启动后，程序会更新电流读数和曲线、累计电荷量，并自动将数据写入 CSV 文件。请同时查看 Save Status，确认文件已正常打开。

运行期间，连接地址、测试按钮、保存路径和保存模式等控件会被锁定。需要修改这些设置时，请先停止监控。

曲线使用各通道所选的电流单位，电荷积分统一以 mC 显示。将鼠标悬停在曲线上，可以查看数据点的信息。

7. 停止监控并开始下一轮

点击 Stop Monitoring，或按 Ctrl+T。程序会停止读取并关闭数据文件，随后恢复可修改的设置。

如果文件名在 .csv 前以“下划线＋四位数字”结尾，停止后输入框中的编号会自动加 1。例如，Run_0000.csv 会变为 Run_0001.csv。不符合这一格式的文件名保持不变。

开始下一轮前，请重新确认文件名和保存模式，再点击 Start Monitoring。每次启动都会重新计算本次运行时间和累计电荷；即使追加到同一文件，也不会接着上一轮的积分值累加。

额外功能

保存快照与查看数据文件

监控运行期间，点击 Create Snapshot 或按 Ctrl+S，可将当前数据文件复制到同一文件夹中。快照文件名带有创建时间，并附加运行时间、电荷积分等说明，便于在采集过程中留存阶段性结果。

快照保存的是创建时的数据；主记录文件仍会继续更新。可通过 File → Open Data Folder 查看原始文件和快照。

CSV 文件中的电流统一换算为 mA，电荷积分统一使用 mC，与界面选择的显示单位无关。各列含义如下：

列名含义
UTC TimestampUnix 时间戳，单位为秒
Run Time (Seconds)本次监控启动后的运行时间，单位为秒
Channel 1 Current (mA)通道 1 电流
Channel 2 Current (mA)通道 2 电流；单通道模式下为 0
Channel 1 Integral (mC)通道 1 本次运行的累计电荷
Channel 2 Integral (mC)通道 2 本次运行的累计电荷；单通道模式下为 0

文件中以 # 开头的行是会话或快照说明。使用数据分析软件导入时，应将这些行作为注释跳过。

过滤异常电流读数

打开 Run → Set Current Threshold，为每个通道设置电流上限，并选择阈值单位。程序会将读数和阈值统一换算为 mA 后比较：电流绝对值超过上限时，该次读数会被丢弃。

过滤以一次采集的整组数据为单位。在双通道模式下，只要任一通道读数无效，本次两个通道的数据都不会显示、写入文件或参与积分，以保持 CSV 中的双通道数据对齐。

阈值设为 0 表示关闭该通道的幅值上限过滤；NaN、Inf 等无效数值仍会被丢弃。

设置状态指示灯和报警音

主界面中，每个通道的电流读数旁都有状态指示灯。它根据采集到的有效读数判断信号状态：

状态含义
RUN（绿色）当前未触发信号异常提醒
PEAK（红色闪烁）电流幅值相对历史基准明显升高，仅用于直流模式
DROP（橙色闪烁）电流幅值相对历史基准明显降低，仅用于直流模式
ZERO（深红色闪烁）电流幅值低于零值阈值，并满足当前模式的报警条件
STOP（灰色）未在监控
OFF通道或该通道的状态监控已禁用

点击指示灯可以手动清除当前的 PEAK、DROP 或 ZERO 警告。如果后续读数仍满足报警条件，警告可能再次出现。连接中断时还应查看日志，不能仅凭指示灯判断设备是否正常通信。

打开 Run → Status Monitor Settings，可分别配置两个通道的状态监控。对话框顶部的 Alarm Sound 是全局报警音开关，默认开启；出现 ZERO 状态时，每 3 秒播放一次系统提示音，状态恢复后停止。

监测直流信号

启用 Enable Status Monitor，保持 Pulse Mode 未勾选，再根据正常信号范围调整以下参数：

参数设置作用
History Window历史窗口长度，单位为秒；窗口内的电流幅值用于计算基准线
Zero Threshold零值阈值；电流绝对值低于此值时触发 ZERO
Threshold Mode选择按幅值差或百分比判断突变
Value Threshold按幅值差判断时使用的阈值
Percent Threshold按百分比判断时使用的阈值
Warning Hold TimePEAK、DROP 警告的保持时间

设置电流阈值时，请留意输入框标示的单位。程序内部会将这些阈值换算为 mA 保存。

监测脉冲信号

对于周期性脉冲，正常的低电平阶段也可能接近零。此时可勾选 Pulse Mode，跳过 PEAK、DROP 检测，只在电流绝对值持续低于 Zero Threshold、且时间超过 Zero Timeout 时触发 ZERO。

Zero Timeout 默认是 3.0 秒，仅在脉冲模式下生效。设置时，应使其长于正常脉冲的低电平持续时间，避免把正常间隔误判为信号丢失。

开启打脉冲提醒

通过 Run → Pulse Reminder 或 Ctrl+Shift+P 开启、关闭打脉冲提醒，默认关闭。这项功能用于提醒操作人员施加脉冲，与状态监控中的 Pulse Mode 分别设置。

若在启动监控前开启提醒，程序会在开始监控约 10 秒后弹出提示。可以选择 No More in This Run，取消本轮后续提醒；也可以选择 Remind in 5 Minutes，在 5 分钟后再次提醒。提醒窗口打开时，采集仍会继续。

与 DAQ 数据获取程序联动

联动功能让电流监控跟随外部数据获取程序自动启停，并按轮次命名保存文件。使用前，请先完成电流表连接测试和单位设置。

在 Run → Connect to DAQ 中选择 DAQ_Master 或 GDDAQ。两种联动互斥，同一时间只能启用一种；均不启用时，使用前文介绍的手动采集方式。

联动期间，保存路径和文件名由外部轮次信息决定，会替代 Save File Name 中手动填写的内容。

使用 DAQ_Master 联动

选择 DAQ_Master，与 “DAQ_Master for BNU LAMBDA” 联动。程序会监测 /tmp/daq_status.txt 的变化，根据其中的状态自动启停。

电流数据按轮次名和编号命名，保存在 DAQ 的 ROOT 数据文件所在目录下的 current_data/ 文件夹中。例如，轮次名为 run、编号为 180 时，电流文件名为 run_00180.csv。

如果没有响应，请确认所用 DAQ_Master 版本支持更新 /tmp/daq_status.txt，并检查文件是否随取数状态变化。文件格式见文末附录。

配置 GDDAQ 联动

启用 GDDAQ 前，先打开 Run → Connect to DAQ → GDDAQ Settings...，完成以下设置：

设置项填写或选择方法
Detection Method选择 run.log (default) 或 Process Memory (root)；联动开启期间不能切换
GDDAQ Version仅内存方式使用，目前支持 GDDAQ-CAEN (20260709)；只能在联动关闭时选择，选择在当前会话内保留
Data Directory数据根目录，例如 /home/rnb/Data/202605ams/raw/；日志方式必填，内存方式可作为目录读取失败时的回退
Process Name日志方式用来检测进程的名称，默认为 gddaq

数据根目录指存放各轮次子文件夹的目录，而非某一轮次的文件夹。例如，raw/ 下可以包含 0001/、0002/，每个轮次文件夹内有自己的 run.log。

程序会自动选择轮次，无需填写 Run Number：日志方式选择编号最大的子文件夹，内存方式跟随实际运行号。

GDDAQ：通过 run.log 检测状态

这是默认方式，无需额外的 root 权限。程序每秒检查一次最大编号轮次中的 run.log，结合 gddaq 进程是否存在来判断取数状态。进程检测依赖 pgrep，本程序的这一联动方式目前用于 Linux。

正常操作时，在 GDDAQ 中开始或停止取数即可：

  • 检测到有效 Start: 记录且进程存在时，自动启动电流监控。
  • 检测到后续 Stop 记录时，自动停止由联动启动的电流监控。
  • 检测到进程退出时，停止联动记录，显示红色异常提示，并等待 GDDAQ 恢复。

如果自动启动失败，例如串口被占用，程序会在后续轮询中重试。具体原因会显示在状态栏，并写入日志；相同错误不会持续重复刷屏。

在同一轮次文件夹中重新开始取数时，需要留意检测延迟。 GDDAQ 可能不会再次写入 Start:，程序因而需要通过“数据文件比 run.log 更新”来识别重启。

这种检测依赖数据写入磁盘，可能延迟约一个数据写盘周期。如果某段取数很短，未产生可识别的文件更新，该段可能漏记；检测到可能漏记的情况时，程序会显示橙色提示，并记录 WARNING。

GDDAQ：通过进程内存检测状态

选择 Process Memory (root) 后，程序会通过辅助子进程，每秒读取一次 GDDAQ 的运行状态、轮次号和数据目录。

启用联动时会弹出密码框，请输入 sudo 密码，用于以 root 权限启动内存读取辅助进程。密码仅用于本次认证，不会被保存或记录。

检测到运行状态后，程序自动开始记录；检测到停止状态后，自动停止联动记录。这种方式无需等待数据写盘即可识别重启，但仍有每秒一次的轮询间隔：完整发生在两次读取之间的短取数段或短暂停顿仍可能遗漏。

使用过程中，异常状态按以下方式处理：

  • 确认 GDDAQ 已退出：在检测到退出时停止联动记录并显示红色提示。辅助进程仍正常运行时，GDDAQ 恢复后可自动继续跟随。
  • 暂时读不到有效状态：短暂失败期间继续记录；连续 3 秒没有有效状态后，在下一次轮询停止并报警。恢复有效状态后，可自动以追加方式恢复记录。
  • 辅助进程退出：停止联动记录，并提示 memory helper exited。请取消再重新勾选 GDDAQ 联动，输入密码后恢复；程序不会自动反复索取密码。

内存状态需要持续更新；重复读取同一份旧状态，或持续收到错误状态，都不会延长上述 3 秒等待期。

目前适配目标为 GDDAQ-CAEN (20260709)。同一版本重新编译后，内部布局也可能变化，因此版本名称相同不代表一定兼容。若日志提示内存读取异常，可在源码目录运行以下诊断命令：

sudo python3 gddaq_memread.py --check

gddaq_memread.py 是独立诊断工具，不随打包程序分发；使用这一命令需要源码中的脚本。

确认 GDDAQ 数据的保存位置

两种 GDDAQ 检测方式都将电流数据追加到数据根目录上一级的 CurrentData/ 文件夹中。例如：

/home/rnb/Data/202605ams/
├── raw/                         ← Data Directory
│   └── 0048/
│       └── run.log
└── CurrentData/
    └── run_00048.csv             ← 电流数据

内存方式优先使用从 GDDAQ 读取的数据目录。旧版日志方式保存在 raw/CurrentData/ 中的文件不会自动搬迁或合并。

当运行号或数据根目录改变时，程序会先关闭旧 CSV，再打开新 CSV。日志方式若发现新轮次尚无有效的 Start:，会停止旧记录并等待。目录、设备连接或文件打开失败时，可查看状态栏和日志；程序会在后续轮询重试。

联动期间如何手动接管

联动期间，启停由外部数据获取程序控制。手动启动会要求确认退出联动；手动停止时，如果外部程序仍在取数，也会要求确认。确认接管后，程序退出联动；取消确认则保持原状态。

每轮取数建议使用新的轮次编号。同一编号重复取数会将多段电流数据追加到同一个 CSV，增加事后对应数据的难度；日志检测方式还存在前述重启延迟和短段漏检问题。

DAQ_Master 也应遵循这一命名习惯：复用相同轮次名和编号，会继续向 current_data/ 下的同名文件追加数据。

查看事件日志与排查问题

主界面绘图区下方的日志栏显示最近一条事件。点击它可打开 Event Log 窗口；窗口打开时，仍可正常操作主程序。

日志从软件启动时开始记录，最多保留最近 100 条，超出后自动移除最早的记录。日志保存在内存中，关闭软件后清空，不会写入磁盘，也不提供清除按钮。

每条日志采用 [时间] [级别] 内容 的格式，并用颜色区分级别：

级别颜色含义
INFO灰色一般事件或操作成功
WARNING橙色需要检查的异常，例如连接测试失败或持续无响应
ERROR红色操作失败，例如连接失败、文件打开失败或快照创建失败

日志包含监控启停、设置应用、连接测试、快照操作和联动异常等信息。启停日志中的括号标明触发来源：

标记触发来源
manual手动操作
daq_masterDAQ_Master 联动
gddaqGDDAQ 联动
daq_disabled取消联动
shutdown关闭程序窗口

GDDAQ 日志检测方式还会在检测到进程出现或消失时记录 INFO，帮助判断问题是否来自获取程序退出。

遇到数据不更新时，可以先查看以下提示，再检查相应设置：

提示或现象建议检查
no data for ~5s检查电流表供电、串口线或网络连接，以及设备是否被其他程序占用
repeated frame CRC/format errors检查波特率和接线；设备持续返回了校验或格式不正确的响应
Save Status 显示文件打开或写入失败检查保存目录、写入权限和磁盘可用空间
memory helper exited取消后重新启用 GDDAQ 内存联动

持续无响应、CRC 校验或帧格式错误通常在约 5 秒后产生 WARNING，恢复后记录 INFO。这类提示会合并重复异常，避免偶发通信问题反复刷屏。

PEAK、DROP、ZERO 仅通过状态指示灯和相应报警音提示，不写入事件日志。逐行保存和绘图刷新也不会产生事件日志，因此排查时应同时观察读数、指示灯、保存状态和日志。

附录：DAQ_Master 状态文件格式

DAQ_Master 通过 /tmp/daq_status.txt 向电流监控程序提供状态。通常由 DAQ_Master 自动更新此文件，用户无需手动编辑。

停止取数时，文件内容为：

STATUS: STOPPED

正在取数时，前四行依次为状态、轮次名、轮次号和 ROOT 数据文件路径。例如：

STATUS: RUNNING
run
180
./12Cag/target1/raw/target1_180.root

以上示例对应的电流文件名为 run_00180.csv，保存在该 ROOT 文件所在目录下的 current_data/ 文件夹中。相对路径应能从电流监控程序的当前工作目录正确解析。
